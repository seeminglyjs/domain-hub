### DB

- [다중 버전 동시성 제어(MVCC, Multi-Version Concurrency Control) 와 VACUUM: PostgreSQL 에 죽은 튜플(Dead Tuple)이 쌓이는 이유](notes/tech/database/2026-11-20-postgresql-mvcc-vacuum-dead-tuples.md) · 2026-11-20  
  PostgreSQL 은 UPDATE · DELETE 때 옛 행을 바로 지우지 않으므로, VACUUM 이 그 공간을 제때 회수해야 테이블과 인덱스가 커지지 않습니다.

### 프레임워크

- [요청 끝까지 열린 영속성 컨텍스트(OSIV, Open Session in View): Spring 이 DB 커넥션을 오래 잡는 이유](notes/tech/framework/2026-11-23-open-session-in-view.md) · 2026-11-23

### 시스템

- [컨테이너 메모리 제한(Container Memory Limit)과 JVM: 힙 밖 메모리(Off-Heap Memory)까지 계산해야 OOM Kill 을 피한다](notes/tech/system/2026-11-24-container-memory-limit-jvm-off-heap.md) · 2026-11-24  
  컨테이너는 JVM 프로세스 전체가 쓰는 메모리로 종료 여부를 판단하므로, 힙 크기는 스레드 스택 · Metaspace · 코드 캐시 · 직접 버퍼를 제외한 나머지로 정해야 합니다.

### 아키텍처

- [펜싱 토큰(Fencing Token) — 락이 만료된 뒤 늦게 도착한 쓰기 막기](notes/tech/architecture/2026-11-12-fencing-token.md) · 2026-11-12  
  락을 내줄 때마다 이전보다 큰 번호를 함께 내주고, 쓰기를 받는 저장소가 이미 본 번호보다 작은 번호의 쓰기를 거절하게 해서, 락이 만료된 줄 모르는 옛 소유자의 쓰기를 막는 방법입니다.

### 언어

- [가상 스레드(Virtual Thread)와 고정(Pinning): 적은 OS 스레드로 많은 요청을 기다리게 하기](notes/tech/language/2026-11-25-virtual-threads-and-pinning.md) · 2026-11-25  
  가상 스레드(Virtual Thread)는 JDK 가 관리하는 가벼운 스레드이며, 블로킹 대기 중에는 OS 스레드를 내려놓지만 고정(Pinning)되면 OS 스레드를 붙잡은 채 기다립니다.

### 대용량 처리

- [대량 적재(Bulk Loading) — PostgreSQL 에 수백만 행을 빠르게 넣기](notes/tech/high-volume-processing/2026-11-18-bulk-loading.md) · 2026-11-18  
  많은 행을 DB 에 한꺼번에 넣을 때 행마다 INSERT 와 커밋을 반복하지 않고, COPY 같은 전용 명령을 쓰고 커밋 · 인덱스 · 제약 조건 · 통계 처리 순서를 바꿔 쓰기 비용을 줄이는 방법입니다.

### 과부하

- [캐시 스탬피드(Cache Stampede) — 만료 순간 몰리는 재계산 막기](notes/tech/overload/2026-11-10-cache-stampede.md) · 2026-11-10
