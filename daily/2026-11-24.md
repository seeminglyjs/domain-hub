## 기술 소식

### 1. JDK 28 에 들어간 JEP 545 가 ZGC 의 힙 준비 작업을 시작 경로에서 떼어 내 시작과 워밍업을 함께 줄입니다.

`백엔드` · 2026-11-23 · 보도

InfoQ 는 JEP 545(ZGC 의 시작 · 워밍업 개선 제안)가 JDK 28 에 통합되었다고 보도했습니다.

이전에는 작은 초기 힙으로 빨리 시작하거나, 큰 초기 힙과 AlwaysPreTouch 로 워밍업을 앞당기는 것 중 하나를 골라야 했습니다.

JEP 545 는 힙 메모리 확보와 준비 작업을 힙 파티션마다 하나씩 도는 동시 작업 스레드로 옮기고, Linux 6.1 이상에서는 실행 중 4KB 페이지를 2MB 페이지로 올립니다.

-XX:+ZAdaptiveHeapSizing 을 켜면 초기 힙을 2MB 로 낮추고 힙 상한을 물리 메모리 100% 까지 허용하며, 기사가 인용한 사례(32GB 머신 · Spring PetClinic)에서 시작 시간이 38% 줄고 워밍업이 80초에서 10초로 줄었습니다.

시작과 워밍업 지연에 민감한 서버를 ZGC 로 운영하는 팀에 유용하며, JDK 28 일반 출시는 2027년 3월 9일 예정입니다.

> 확인할 점: 컨테이너에서 이 옵션을 시험할 때는 힙 상한이 컨테이너 제한 전체로 커질 수 있으므로 힙 밖 메모리 여유분을 따로 잡아 두었는지 확인해야 합니다.

출처: [InfoQ: JEP 545 Moves ZGC Memory Preparation off the Startup Path in JDK 28](https://www.infoq.com/news/2026/11/jep-545-jdk-28/)

### 2. Kubernetes v1.38 미리보기 글이 cgroup 드라이버 보고 방식 변경과 kubectl WebSocket 옵트아웃 변수 제거를 예고했습니다.

`인프라·보안` · 2026-11-23

Kubernetes 프로젝트가 12월 16일 출시 예정인 v1.38 의 지원 종료 · 제거 · 주요 변경 항목을 미리 정리한 글을 올렸습니다.

컨테이너 런타임은 CRI(Container Runtime Interface, kubelet 과 런타임 사이 규약) 의 RuntimeConfig 호출로 cgroup 드라이버를 알려야 하며, 이전 방식은 기본으로 허용되지 않습니다.

kubectl 의 KUBECTL_REMOTE_COMMAND_WEBSOCKETS · KUBECTL_PORT_FORWARD_WEBSOCKETS 환경 변수는 제거되어 exec · port-forward 가 WebSocket 을 끄는 선택지가 사라집니다.

cgroup v1 지원은 이후 버전에서 제거될 예정이며, 그때까지는 kubelet 설정 failCgroupV1: false 로 임시 유지할 수 있다고 안내합니다.

클러스터를 직접 올리는 팀과 오래된 노드 이미지를 쓰는 팀이 업그레이드 전에 점검할 목록으로 쓸모 있습니다.

> 확인할 점: 업그레이드 전에 노드의 containerd 같은 런타임 버전이 RuntimeConfig 를 지원하는지와 노드가 cgroup v2 로 도는지 확인해야 합니다.

출처: [Kubernetes Blog: Kubernetes v1.38 Sneak Peek](https://kubernetes.io/blog/2026/11/23/kubernetes-v1-38-sneak-peek/)

### 3. Agoda 가 예약 후 API 를 모듈러 모놀리스(Modular Monolith) 구조로 묶어 코드 리뷰 완료 시간 중앙값을 약 64% 줄였다고 밝혔습니다.

`아키텍처·운영` · 2026-11-23 · 보도

여행 예약 회사 Agoda 가 예약 뒤 취소 · 재예약 · 결제를 다루는 API 에 Platform 이라는 내부 프레임워크를 도입한 결과를 공개했습니다.

이 API 는 2019년 큰 단일 서비스에서 떼어 냈지만, 2022~2025년 변경 요청 수가 4배 이상 늘며 4,000줄이 넘는 파일이 생겼습니다.

서비스를 다시 쪼개는 대신 코드를 도메인 단위 모듈로 묶고, ArchUnit(Java 코드 구조 규칙을 단위 검사로 확인하는 라이브러리) 규칙을 CI 에서 돌려 모듈 사이 의존을 막았습니다.

2026년 2분기 기준 새 구조 변경 요청의 리뷰 완료 시간 중앙값은 1.08시간으로 기존 구조의 3.02시간보다 약 64% 짧았고, 첫 실질 피드백까지 시간도 약 34% 줄었습니다.

회사는 관찰 기간이 짧아 방향성 참고치라고 밝혔으며, 큰 단일 서비스의 결합도와 리뷰 병목을 고민하는 팀에 참고가 됩니다.

> 확인할 점: 서비스를 나누기 전에 패키지 의존 방향을 검사 코드로 고정해 모듈 경계를 먼저 지킬 수 있는지 시험해 볼 만합니다.
