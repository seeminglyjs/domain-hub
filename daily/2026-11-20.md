# 2026-11-20 (금) 지식 노트

> 대상 기간 11-19 10:00 ~ 11-20 10:00 · [전체 색인](../README.md) · [용어 색인](../glossary.md)

## 핵심

1. **기술** · PostgreSQL 19 가 정식 출시되어 테이블을 막지 않고 공간을 회수하는 REPACK (CONCURRENTLY) 와 autovacuum 우선순위 점수가 들어왔습니다.  
   확인할 점: 업그레이드 전에 JIT 기본 비활성화 · io_workers 설정 교체 · md5 인증 경고 같은 호환성 변경을 릴리스 노트에서 확인합니다.
2. **기술** · Java4Shell(CVE-2026-114938) 을 노리는 탐색과 악용 시도가 관측되기 시작했다는 보도가 나왔습니다.  
   확인할 점: AVX-512 VBMI 를 지원하는 x86-64 서버에서 Java 17 이상을 돌린다면 11월 패치 빌드로 교체했는지 확인합니다.

## 기술 소식

### 1. PostgreSQL 19 가 정식 출시되어 테이블을 막지 않는 REPACK (CONCURRENTLY) 와 autovacuum 우선순위 점수가 들어왔습니다.

`데이터·DB` · 2026-11-19

PostgreSQL Global Development Group 이 11월 19일 PostgreSQL 19 정식 버전을 발표했습니다.

지금까지 공간을 회수하는 VACUUM FULL · CLUSTER 는 테이블 접근을 막았지만, 새 REPACK (CONCURRENTLY) 는 읽기 · 쓰기를 막지 않고 테이블을 다시 씁니다.

autovacuum 은 처리할 테이블에 우선순위 점수를 매기고(pg_stat_autovacuum_scores 뷰로 확인), autovacuum_max_parallel_workers 로 인덱스 정리를 병렬로 할 수 있습니다.

발표문은 외래 키 검사 개선으로 대량 INSERT 가 시험에서 거의 2배 빨라졌다고 밝혔고, 스탠바이에서 특정 WAL 위치까지 기다리는 WAIT FOR LSN 과 락 종류별 통계 뷰 pg_stat_lock 도 더했습니다.

업그레이드 주의 사항으로 JIT(Just-In-Time 컴파일) 기본 비활성화 · io_workers 를 io_min_workers · io_max_workers 로 교체 · md5 비밀번호 인증 경고 · RADIUS 인증 제거가 적혀 있습니다.

큰 테이블의 부풀음 정리 때문에 점검 시간을 잡아 온 서비스에 특히 쓸모가 있습니다.

> 확인할 점: 업그레이드 계획 전에 릴리스 노트의 호환성 변경 목록과, 분석 쿼리가 JIT 비활성화로 느려지는지를 확인합니다.

출처: [PostgreSQL 19 Released!](https://www.postgresql.org/about/news/postgresql-19-released-3449/)

### 2. Java4Shell(CVE-2026-114938) 을 노리는 탐색과 악용 시도가 관측되기 시작했다는 보도가 나왔습니다.

`인프라·보안` · 2026-11-19 · 보도

SecurityWeek 는 11월 19일 GreyNoise · watchTowr · Cloudflare 가 Java4Shell 탐색과 악용 시도를 관측했다고 보도했습니다.

Java4Shell 은 OpenJDK 17.0.6 이상의 Base64 디코딩 하드웨어 가속 경로에서 생기는 메모리 손상 취약점이며, AVX-512 VBMI 를 지원하는 x86-64 CPU 에서만 악용할 수 있고 ARM 서버는 해당하지 않습니다.

기사에 따르면 GreyNoise 는 11월 19일 오전까지 IP 5개에서 공격 형태의 요청 150건 이상을 기록했지만 성공한 침입은 보지 못했습니다.

Red Hat 은 JVM 이 별도 설정 없이 가속 경로를 자동으로 고르므로 기본 설정에서도 취약하다고 밝혔고, Amazon · Microsoft · Azul 은 패치된 OpenJDK 빌드를 내놓았습니다.

Elasticsearch · Jenkins · Keycloak · Atlassian Data Center 제품 등도 각자 권고를 냈으며, Atlassian 은 패치 전 임시 회피책으로 AVX-512 비활성화를 안내했습니다.

Java 서버를 x86-64 가상 머신이나 컨테이너로 운영하는 팀이 대상입니다.

> 확인할 점: 운영 중인 JVM 이미지의 Java 버전과 서버 CPU 의 AVX-512 VBMI 지원 여부를 확인하고, 11월 패치 빌드로 교체합니다.

출처: [SecurityWeek: Java4Shell Exploitation Attempts Begin](https://www.securityweek.com/java4shell-exploitation-attempts-begin-as-vendors-rush-out-advisories/)
