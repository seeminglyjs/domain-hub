## 핵심

1. **기술** · Cloudflare 가 Java4Shell(OpenJDK Base64 디코더 취약점)을 탐지하는 WAF 규칙 6개를 내놓고, 패치 전 임시 회피 방법으로 JVM 옵션을 안내했습니다.  
   확인할 점: 컨테이너 이미지에 함께 들어간 JDK 까지 버전을 확인하고, 바로 올릴 수 없으면 -XX:-UseBASE64Intrinsics 를 임시로 검토합니다.
2. **기술** · PostgreSQL 백업 도구 WAL-G 3.0.10 이 객체 저장소의 WAL 을 복제 프로토콜로 내보내는 wal-send 와 백업 완료 전 WAL 도착을 기다리는 옵션을 더했습니다.  
   확인할 점: WAL-G 로 백업하는 서비스라면 backup-push --wait-for-archive 적용과 영구 백업 삭제 동작 변경을 확인합니다.

## 기술 소식

### 1. Cloudflare 가 Java4Shell 을 탐지하는 WAF 규칙 6개와 패치 전 임시 회피 방법을 공개했습니다.

`인프라·보안` · 2026-11-18

Cloudflare 가 11월 17일 공개된 Java4Shell(CVE-2026-114938, OpenJDK Base64 디코더의 메모리 손상 취약점)에 대응하는 WAF(Web Application Firewall, 웹 요청을 검사해 공격을 거르는 장치) 관리 규칙 6개를 내놓았습니다.

취약점은 x86-64 프로세서에서 AVX-512 명령어를 쓰는 Base64 디코딩 가속 경로에 있으며, 잘못된 패딩 입력이 음수 출력 길이를 만들어 배열 밖에 64바이트를 쓰게 됩니다.

규칙은 헤더 · 쿼리 값 · 본문 · 경로 · JWT(JSON Web Token, 서명된 인증 토큰) 구성 요소 · WebAuthn 값에서 잘못된 Base64 입력 모양을 찾으며, 정상 요청을 막을 수 있어 기본은 기록(Log) 모드입니다.

Cloudflare 는 WAF 가 내부 통신 · HTTP 가 아닌 프로토콜 · 인코딩된 데이터까지는 볼 수 없으므로 모든 Java 실행 환경을 업데이트하고 재시작하는 것만이 완전한 해결이라고 밝혔습니다.

바로 패치할 수 없는 경우의 임시 방법으로 JVM 옵션 -XX:-UseBASE64Intrinsics 를 안내했으며, 이 옵션은 성능을 낮출 수 있습니다.

> 확인할 점: 애플리케이션 서버뿐 아니라 컨테이너 이미지와 배포 묶음에 함께 들어간 JDK 버전까지 확인하고, 업데이트 전이라면 임시 JVM 옵션의 성능 영향을 측정합니다.

출처: [Cloudflare Blog: How Cloudflare WAF helps protect against Java4Shell](https://blog.cloudflare.com/java4shell-waf-protection/)

### 2. WAL-G 3.0.10 이 객체 저장소의 WAL 을 복제 프로토콜로 내보내는 wal-send 를 더했습니다.

`데이터·DB` · 2026-11-18

WAL-G(PostgreSQL · MySQL · Redis 등 여러 DB 를 지원하는 오픈소스 백업 · 복구 도구) 3.0.10 이 나왔습니다.

새 명령 wal-send 는 객체 저장소에 보관된 WAL(Write-Ahead Log, 변경 내용을 먼저 적는 로그)을 PostgreSQL 스트리밍 복제 프로토콜로 내보내, 대기 서버(Standby)와 pg_receivewal 이 객체 저장소에서 바로 WAL 을 읽고 새 구간을 따라가게 합니다.

backup-push --wait-for-archive 옵션을 쓰면 백업에 필요한 WAL 구간이 모두 백업 저장소에 도착한 뒤에야 백업을 완료로 표시합니다.

S3 연동은 AWS SDK v2 로 바뀌어 요청 시간 제한 · 재시도할 오류 코드 · 체크섬 설정을 지정할 수 있고, 백업 복사는 S3 서버 측 복사와 전송 동시 실행 수 설정을 쓸 수 있습니다.

동작 변경으로 영구(permanent) 백업은 보관 기간 기반 삭제에서는 계속 보호되지만, 명시적인 delete target 명령으로는 지울 수 있게 되었습니다.

> 확인할 점: WAL-G 로 PostgreSQL 을 백업하는 서비스라면 WAL 이 누락된 백업을 막는 --wait-for-archive 적용과 영구 백업 삭제 동작 변경을 업그레이드 전에 확인합니다.
